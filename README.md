# Рядом — личный дневник знакомств

Сайт: https://closeby-notebook-k7m4.finiterose64.chatgpt.site

Публичный сервис: любой человек может войти через ChatGPT и создать свой дневник. Анкеты, фото и ключи ботов изолированы по аккаунтам. Анкеты в Cloudflare D1, фотографии в R2. Данные локального предпросмотра не публикуются.

## Возможности

Анкеты: имя, возраст 18+, город, контакт, источник знакомства, день рождения, интересы, предпочтения, описание. До 20 фото JPG/PNG/WebP по 10 МБ на анкету. Заметки с датами, избранное, поиск по всем деталям, фильтры и сортировка. Этапы общения, архив с восстановлением, полное удаление с фотографиями. Встречи с местом и временем, отдельные списки будущих и прошедших встреч. Время — местное время устройства; автоматических уведомлений нет.

JSON-копия включает фотографии и даты заметок. Восстановление создаёт новые анкеты; повторный импорт создаст дубликаты. Максимальный файл импорта — 150 МБ, до 1000 анкет.

## Telegram

По просьбе владельца бот **подготовлен, но не подключён**. Для работы нужен бот от @BotFather и процесс на постоянно работающем компьютере или сервере. Бот использует long polling и API с личным ключом. Публичность главной страницы не открывает доступ к анкетам.

1. Создать бота в [@BotFather](https://t.me/BotFather) командой `/newbot` и сохранить токен в секрете.
2. Узнать свой числовой Telegram ID. В конфигурации явно указывается владелец; первый написавший не становится владельцем.
3. На сайте в разделе «Telegram-бот» создать ключ. Он показывается один раз; в БД хранится только SHA-256 хеш. Отзыв ключа немедленно блокирует доступ.
4. Для действующего публичного сайта `SITE_ACCESS_TOKEN` не требуется. Эта переменная нужна только при размещении на закрытом Sites и не публикуется.
5. Локально создать `bot/.env` по `bot/.env.example` (игнорируется Git):
   - `TELEGRAM_BOT_TOKEN` — токен BotFather;
   - `TELEGRAM_OWNER_ID` — числовой ID владельца;
   - `SITE_URL` — адрес сайта выше;
   - `SITE_ACCESS_TOKEN` — оставить пустым для публичного сайта;
   - `NOTEBOOK_KEY` — ключ, созданный на сайте;
   - `BOT_STATE_FILE` — файл offset и выбранной анкеты, по умолчанию `.bot-state.json`.
6. Ограничить доступ к файлу: `chmod 600 bot/.env`.
7. С Node.js 22+ запустить из корня проекта:

```sh
node --env-file=bot/.env bot/telegram-bot.mjs
```

Для постоянного запуска с Docker Compose: из каталога `bot` выполнить `docker compose up -d --build`. Токены в образ не копируются; состояние сохраняется в отдельном томе. Круглосуточная работа требует постоянно работающего процесса.

Бот принимает только сообщения владельца в личном чате. Изменения и фото появляются на сайте. Команды: `/help`, `/add Аня`, `/find Аня`, `/list`, `/select ID`, `/show`, `/set likes Матча`, `/note Любит пионы`, `/status chat`, `/meet 2026-12-01T19:00 | Кафе`, `/favorite`, `/archive`, `/restore`, `/removephoto ID`. Обычный текст сохраняется заметкой, фото прикрепляется к выбранной анкете. Удаление требует отдельного подтверждения с ID в течение двух минут.

`/export` выгружает JSON-копию с фото; если фото суммарно больше 40 МБ, копию нужно скачивать с сайта. Повторные доставки команд и фото от Telegram не дублируют успешно записанные изменения. Offset и выбранная анкета сохраняются между перезапусками. Существующий webhook не удаляется: запуск останавливается и сообщает о конфликте. Ошибки отдельных команд отправляются владельцу; при необходимости команду можно повторить.

Документация: [Telegram Bot API](https://core.telegram.org/bots/api), [BotFather](https://core.telegram.org/bots/features#botfather).

## Локальная разработка

Node.js 22+ с `node:sqlite`. Зависимости npm не требуются.

```sh
node scripts/build.mjs
node --test tests/*.test.mjs
node scripts/validate-artifact.mjs
node scripts/dev.mjs
```

Предпросмотр слушает только `127.0.0.1:4173` и использует отдельного локального пользователя. SQLite и фото — в игнорируемом `.local/`. Локальный адаптер не используется в опубликованном сайте. После сборки перезапустить dev-процесс и обновить страницу.

Исходники: `web/` — интерфейс, `worker/server.js` — API, `bot/` — бот, `drizzle/` — миграции. Сборка встраивает страницу и скачиваемого бота в Worker ES module. Публикация — через официальный Sites workflow с сохранением ID, привязок DB/BUCKET и личного доступа.

Автоматические проверки: CRUD, архив, заметки, изоляция пользователей, даты и возраст, защита Origin, фотографии и их удаление, ключи бота и их отзыв, идемпотентность, импорт дат заметок, сборка. Реальное соединение с Telegram требует токена и пока не проверялось.
